## 8. Формы

Для каждой формы описывать:

### [Название формы]

**Поля:**

| Поле        | Тип    | Обязательное | Валидация               |
|-------------|--------|--------------|-------------------------|
| Имя         | text   | Да           | minlength: 2            |
| Email       | email  | Да           | Формат email            |
| Сообщение   | textarea | Нет        | maxlength: 1000         |

**Логика отправки:**

1. Клиентская валидация в реальном времени (при blur)
2. Показ inline-ошибок под полями
3. Кнопка отправки → состояние loading
4. Запрос к API / сервису
5. Успех → toast уведомление + сброс формы
6. Ошибка → toast с описанием + форма остаётся заполненной

**Сервис отправки:**

* Formspree / Resend / собственный API / Netlify Forms

**Accessibility:**

* `<label>` связан с `<input>` через `for` / `id`
* Ошибки связаны через `aria-describedby`
* Поля с ошибкой имеют `aria-invalid="true"`

## 15. Критерии готовности

Сайт считается готовым к деплою если:

* Все страницы из роутинга реализованы
* Mobile (360px) отображается корректно
* Lighthouse: Performance ≥ 90, Accessibility ≥ 90, Best Practices ≥ 90, SEO ≥ 90
* CLS < 0.1 на всех страницах
* Все формы работают (отправка + обработка ошибок)
* 404 страница настроена
* OG-изображения сгенерированы
* sitemap.xml и robots.txt настроены
* Шрифты загружаются локально или через preconnect
* Нет broken links
* Нет ошибок в браузерной консоли
* `prefers-reduced-motion` протестирован
* Keyboard navigation протестирован
* Screen reader проверен (axe или NVDA/VoiceOver)

# Стиль написания ТЗ

Всегда:

* Конкретные тексты, цвета, размеры — не "синяя кнопка", а `background: #6366F1, border-radius: 10px`
* Таблицы для сравнений и списков параметров
* ASCII-схемы для layouts
* Примеры кода для нестандартных решений
* Явные ссылки на DESIGN_RULES.md и AGENTS.md где применимо

Избегать:

* "красивый дизайн" без конкретики
* "современные анимации" без описания что именно
* "адаптивный" без описания брейкпоинтов
* "быстрый" без целевых метрик
